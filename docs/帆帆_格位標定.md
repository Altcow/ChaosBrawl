## 0. 重要發現(先看)

1. **圖上其實是 25 個姿勢,不是 24 格。** 第 2 排畫了 7 個(第 1、3、4 排各 6 個)。檔名「24格」保留不改,但切圖設定要寫 25 個幀名。
2. **第 2 排第 4 格(蹲)和第 5 格(跳)左右重疊 3 px。** 切圖工具 components 版面會依外框合併碎塊,預設 `mergeGap` 會把這兩格併成一格(實測 `mergeGap: 2` 只切出 24 格,其中一格寬 155 px)。
   - 解法(已在暫存區實測通過):`"mergeGap": -6`。合併條件 `a.x0 - gap < b.x1 …` 在 gap 為負時,外框要重疊超過 6 px 才合併;這張圖除了身體本身沒有分離碎塊(像素面積 < 300 的碎塊 0 個),所以負值安全。實測輸出 25 格、圖集 1982×192。
   - `sheet.mergeGap || C.mergeGap`:負數是 truthy,會生效。
3. **切圖工具只讀 PNG**(`png.mjs`)。webp 要先轉成 PNG(例如 Python PIL `Image.open(...).convert('RGB').save('帆帆_標準圖.png')`),再給 slice.mjs。
4. components 版面**沒有 air 錨點**(`air` 只在 grid 有效),所有格都以外框底為腳底。空中格(jump_up、dash_0、fall_up、roll_1)貼地對齊,高度由引擎的 y 位移表現,接受。
5. 頭髮邊緣、蝴蝶結附近有少量粉紅反光(第 2、3 排較明顯),去背後可能留粉邊;dev 切完看一下,必要時調 `key.lo`。

### 1-1 排序規則

`slice.mjs` 的 components 版面:先找連通區域 → 合併近距離碎塊 → `sortRowMajor()`:
- 依外框中心 y 分列,列容差 = 最高外框高度的一半(這張約 106 px;各排中心 y 約 147 / 400 / 655 / 910,間距約 250,不會混列)。
- **列優先(由上到下),同列由左到右(依外框左緣 x0)。**
- frames 陣列第 n 個名字 = 排序後第 n 格。
